「気になるニュース」の投稿を作ります。出典：$ARGUMENTS

CLAUDE.md の「気になるニュース」「情報の根拠」「健康情報のルール」「文体」を必ず守ってください。見本は posts/2026-10-16-news-tairyoku です（ただし publishDate は使わず、newsCategory・created を書く）。
運営者の OK（クラウドではプルリクエストのマージ）が出たら、時間に関係なくすぐ Instagram・Threads に投稿します（YouTube には上げません）。アプリ（"app": true）には作った日の翌日0時から載ります。
返事・報告はすべて日本語で書きます。下の **【止まる】** では、必ず運営者の返事を待ってから次へ進みます。

## 0. PC かクラウドかを確かめる

- `gh --version` が動けば **PC の流れ**（A）、動かなければ **クラウドの流れ**（B。スマホの Claude アプリの Code など）で進める
- 1〜3 はどちらも同じ

## 1. 最新にする

- `git pull` を実行する（クラウドで main 以外のブランチにいるときは `git fetch origin main` して、origin/main をもとに作業する）

## 2. 出典と一次資料を読む

渡されたもの（$ARGUMENTS）は、次の2つの形のどちらか。

- **出典のURLだけ**：そのページを開いて読む
- **「②」などの丸数字で始まる朝ラジオのメモ**（日付・分野・見出し・要約・出典のリンクが書かれた文）：
  - 丸数字は、その日の朝ラジオで何番目の話題かを表す。メモに話題がいくつも書かれているときは、その番号の話題だけを使う（どれかわからなければ運営者に聞く）
  - メモは**出発点（何の話題か・どこを探すか）**として使うだけ。見出し・要約の数字や言い回しは、そのまま投稿に使わない
  - メモの出典のリンクを開いて読む。開けない・リンクがないときは、見出しと要約の言葉で、発表元のサイトを探す
  - 見出し・要約に出てくる数字は、**すべて一次資料で確かめ直す**。一次資料と食い違う数字・一次資料にない数字は使わず、A-4／B-5 の報告で「メモの数字 → 一次資料の数字（出典）」として知らせる
  - 表紙の date は、ラジオの日付ではなく、一次資料に書かれた発表日にする
  - 要約にない内容も一次資料から読み込んで、いつもどおりのスライドにする（発表の目的・調べ方・対象・結果・注意書きなど）

どちらの形でも、次を守る（URL もメモもなければ、何の話題か運営者に聞く）。

- 出典が報道・まとめ記事のときは、そのもとになっている国・自治体・大学・学会などの一次資料（報道発表・PDF）を探して開き、読む。出典がもともと一次資料なら、その本文と添付の資料（PDF）まで読む
- 使う数字は、一次資料で確かめられたものだけにする。確かめられない数字は使わない
- 一次資料が見つからない・内容があいまいなときは、作る前に運営者に確認する
- 読んだ資料のURLは、すべて post.json の "sources" に入れる

## 3. post.json を作って render する

- フォルダ：`posts/今日の日付-news-英数字/`（今日＝作った日）
- "category": "健康ニュース"。"publishDate" は書かない
- "newsCategory"：メモの「分野」から "医療・介護"・"健康"・"AI" のどれかを書く（URL だけのときは内容から決めて、A-4／B-5 で報告する。運営者が「分野：〇〇」と書いていればそれに従う）
- "created"：今日（作った日）の日付
- 運営者の依頼に **「アプリにも」** があれば "app": true を書く。AI のニュースでは書かずに、「AI のニュースはアプリに載せない決まりです」と伝える
- cover（title 1行6文字×3行・subtitle に発表元・date に発表日）と slides（facts / bars / compare / bignum、最後は actions）で作る
- ルールの確認（特に）
  - 「関係があった」と「効果があった」を分けて書く
  - 長い期間の傾向と最近の傾向を混ぜない。どちらの期間の話かをはっきり書き、スライド・キャプション・Threads で食い違わないようにする
  - 効果を保証する言い方・病名を挙げて効果をうたう言い方をしない
  - actions の note に「痛みやふらつきがある方は、かかりつけ医にご相談ください。」などの一文を入れる
- caption（post.json）：最初の1行で読者の思い込みや悩みに触れる →【気になる健康ニュース】と発表の中身 → 最後に「参考：機関名「資料名」（年）」。hashtags は「120歳まで歩く」「理学療法士」を入れて10〜15個
- `npm run render -- posts/フォルダ名` を実行する（caption.txt もできる）
- できた images/ の画像を自分で全部開いて、はみ出し・不自然な改行・縮みすぎがないか確かめ、あれば直して render し直す
  - クラウドで render できない（Playwright・フォントの準備ができていない）ときは、そのことを伝えて、画像の確認は B-2 のプレビューで行う

## A. PC の流れ（gh が使える）

### A-4. 見せて確認を待つ 【止まる】

- 次を運営者に見せる
  - 画像（各スライドのPNGの場所と、気になった点）
  - キャプションの全文
  - Threads 3投稿の文（threads.json がなければ `scripts/threads-lib.js` の buildThreadTexts で作られる文を出して見せる）
  - 使った一次資料と、数字ごとの出典（朝ラジオのメモから作ったときは、メモの数字と一次資料の数字が合っていたか・食い違っていたか）
  - 分野（newsCategory）・アプリに載せるか（app）
  - 「確認OK」のあと、すぐ Instagram・Threads に投稿すること（YouTube には上げない。アプリは作った日の翌日0時から）
  - リール動画（`npm run reel -- posts/フォルダ名` で作った reel.mp4 を開いてもらう）
- 直す点を言われたら直して、render して、もう一度見せる
- 運営者が「確認OK」と言うまで、commit・push はしない

### A-5. 「確認OK」のあと：push して、すぐ投稿する

- `npm run queue` を実行して、その分野の枠の予定とアプリ用ニュースを確かめる
- `git add -A` → `git commit` → `git push`（ref/ など投稿に関係ないものは入れない）。push した時点でストックに入る
- `gh workflow run instagram.yml -f slot=枠 -f folder=フォルダ名` で、すぐ投稿する（枠は news-care・news-health・news-ai）
- 実行が終わるのを待ち（`gh run watch`）、`git pull` して posted.json・threads-posted.json を確かめ、各投稿のリンクを報告する
  - Threads が途中で止まったときは、**【止まる】** 続きを出す前に運営者に確認する（OK が出たら `gh workflow run threads-thread.yml -f folder=フォルダ名 -f dry_run=false` で続きから出す）

## B. クラウドの流れ（gh が使えない。プルリクエストで確認する）

確認は GitHub のプルリクエストで行い、**マージ＝本番OK（すぐ投稿）** になります。Claude は、運営者に頼まれたときだけマージします。

### B-4. ブランチに commit して push する

- ブランチ：いま `claude/` で始まるブランチにいるときはそのまま使う。それ以外は `news/フォルダ名` を作る（`git checkout -b news/フォルダ名 origin/main`）
- `git add posts/フォルダ名` → `git commit` → `git push -u origin HEAD`（ref/ など投稿に関係ないものは入れない。schedule.json・app-feed は入れない）
- push すると、GitHub Actions「健康ニュースのプレビュー」（.github/workflows/news-preview.yml）が自動で次を行う（5分ほど）
  - プルリクエストを作る（gh がなくてもよい）
  - render して画像をブランチにコミットする（そのあとは `git pull` してから直す）
  - 画像URL・トークンの確認（dry_run）
  - リール動画を作って、プレビュー用のリリース（news-preview-フォルダ名）に置く
  - プルリクエストに、画像6枚・リール動画のリンク・キャプション・Threads 3投稿の文・YouTube のタイトルをコメントする
- プルリクエストの番号は、`curl -s "https://api.github.com/repos/kai061228-stack/120lab-content/pulls?head=kai061228-stack:ブランチ名"` で調べられる（読むだけならログイン不要）

### B-5. 確認をお願いする 【止まる】

- 運営者に次を伝える
  - プルリクエストのリンク（わからなければ https://github.com/kai061228-stack/120lab-content/pulls ）
  - キャプションの全文、Threads 3投稿の文、使った一次資料と数字ごとの出典（朝ラジオのメモから作ったときは、メモの数字との食い違い）、分野・アプリに載せるか
  - 「コメントの画像と動画を確認して、よければマージしてください。マージすると、すぐ Instagram・Threads に投稿します（YouTube には上げません）」
- 直す点を言われたら、同じブランチで直して commit・push する（プレビューのコメントが作り直される）

### B-6. マージのあと（Actions が自動で行う）

- ワークフロー「健康ニュースの本番投稿」（.github/workflows/news-publish.yml）が、instagram.yml を slot＝分野の枠・folder＝フォルダ名で起動して、すぐ投稿する（時間に関係なく）
- 終わると、各投稿のリンク（Instagram・Threads）がプルリクエストにコメントされる。運営者に聞かれたら、そのコメントを読んで伝える
- すぐの投稿が失敗したときは、ストックに残り、その分野の枠で予定表どおりに出る
- Threads が途中で止まったときは、**【止まる】** 続きは自動では出さない。運営者の OK が出たら、GitHub のアプリかブラウザで Actions →「Threads 連投」→ Run workflow（folder=フォルダ名、dry_run を外す）を実行してもらう
