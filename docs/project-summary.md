# 120歳まで歩くラボ Instagram自動投稿プロジェクト まとめ

最終更新：2026年9月26日

## 1. 目的と方針

- 目的：「120歳まで歩くラボ」の健康情報をInstagramで毎日発信し、集客につなげる
- 読者：介護をしている方・介護を受けている方・介護職の方（シニア層中心）
- 方針
  - Claude Code 以外は無料ツールで運用する
  - 作業の大部分はClaude Codeに任せ、内容の最終確認は理学療法士（かい）が行う
  - 健康情報は事実ベース（公的機関・学会・職能団体・報道機関の情報）で発信する
  - 1週間分ほどをまとめて確認し、自動で順番に投稿する

## 2. 仕組みの全体像

| 項目 | 内容 |
|---|---|
| 作業フォルダ（PC） | `C:\120lab-content` |
| GitHubリポジトリ | https://github.com/kai061228-stack/120lab-content （公開） |
| 投稿先アカウント | Instagram @120arukulab（プロアカウント） |
| Metaアプリ | 120lab-autopost（Instagramログイン方式のAPI、開発モード。@120arukulab をInstagramテスターとして登録済み） |
| 認証情報 | GitHub Secrets に `IG_ACCESS_TOKEN` と `IG_USER_ID`（17841440387143234）を保存。トークンはファイルやチャットに書かない |
| 自動投稿 | GitHub Actions「Instagram 自動投稿」を毎朝5:00に外部サービスから起動（予備として GitHub の定時起動が5:20）。予定表 schedule.json の今日の投稿を出す |
| 投稿内容 | 1日1件。カルーセル（画像）を投稿したあと、同じ画像を動画にしたリール（BGM付き）も投稿 |
| リール動画の置き場 | GitHub Pages（gh-pagesブランチ）。毎回その日の1本だけで上書き。手で編集しない |

### 投稿の流れ

1. PCでClaude Codeに投稿を作ってもらう（post.json → 画像作成）
2. `npm run preview` で一覧を確認し、内容をチェック
3. `npm run queue` で投稿予定を確認（schedule.json と app-feed/feed.json も作り直される。push 後は Actions でも自動で作り直す）
4. コミットして GitHub に push（pushしないと投稿されない）
5. 毎朝、GitHub Actions が予定表の今日の1件を、カルーセル → リールの順に投稿（健康アプリにも同じ投稿が0時から表示される）
6. 投稿済みのフォルダには `posted.json` が自動で追加される（二重投稿防止）。PCでは作業前に `git pull`

## 3. 投稿のルール

### カテゴリーと見た目

| カテゴリー | 色 | 表紙ラベル | キャラクター（かいたろ君） | リールBGM（甘茶の音楽工房） |
|---|---|---|---|---|
| 運動 | オレンジ | 体操 | ダンベルを持つ姿 | はじめてのおつかい |
| 知識 | 青 | からだの知識 | 本と電球を持つ姿 | フィヨルドの澄んだ風 |
| 啓発 | 緑 | 暮らしのヒント | 胸に手とグッドサイン | 聖夜 |

- 画像：1080×1350（4:5）のカルーセル。表紙＋ポイント3〜5枚＋まとめ
- 表示名：@120歳まで歩くラボ／左上にページ番号、表紙に「スワイプで見る」
- リール：9:16、表紙3秒・2枚目以降6秒、フェードで切り替え、最後2秒でBGMフェードアウト
- リールのキャプションには、ハッシュタグの前に「BGM：甘茶の音楽工房」を自動で入れる（カルーセルには入れない）

### 投稿の順番

- 運動 → 知識 → 啓発 の順に1日1件ずつローテーション
- 同じカテゴリーの中では、フォルダ名の順（古いもの）から
- その日のカテゴリーがなければ次のカテゴリーから繰り上げ
- 特定の日に出したい投稿は post.json に `"publishDate": "YYYY-MM-DD"` を書く（「〇〇の日」などの記念日に合わせる）
- ストックの目安：各カテゴリー3件以上

### 文字量の目安

- 表紙タイトル：1行7文字以内×2行／サブタイトル：20文字以内
- ポイント見出し：1行8文字以内×2行
- ポイント本文：50文字以内。`\n` で区切った1行は14文字以内（画像ありは17文字）、4行まで
- 表紙タイトルと見出しは、2行目を助詞（の・に・が・を など）で始めない
- まとめの項目：1項目10文字以内
- cta（最後のボタン）：16文字以内、語尾は「〜しましょう」
- キャプション：300〜500文字、最初の1行で読者の悩みに触れる
- ハッシュタグ：10〜15個。「120歳まで歩く」「理学療法士」は必須

### 健康情報・根拠のルール

- 公的機関（厚労省、JIHS、気象庁、内閣府、消費者庁、自治体など）、学会、職能団体（日本理学療法士協会など）、報道機関の情報にもとづいて書く
- 参照したURLを post.json の `sources` に記録し、キャプションの最後に「参考：機関名」を入れる
- 数字は出典どおりに使い、年も書く
- 「治る」「免疫力アップ」など効果を断定しない（医療広告・薬機法への配慮）
- 運動の回数・秒数は出典に合わせ、「痛みが出たら中止」「回数は体力に合わせて調整」を入れる
- まとめに受診を勧める一文を入れる
- 出典が見つからない内容は書かない。迷ったら理学療法士が判断する

## 4. よく使うコマンド（Claude Code／PowerShell）

| コマンド | 内容 |
|---|---|
| `claude` | `C:\120lab-content` で起動。CLAUDE.md のルールが自動で読み込まれる |
| `npm run render -- posts/フォルダ名` | 1件の画像を作る（PNGとJPEG） |
| `npm run all` | 全投稿の画像を作り直し、preview.html を更新 |
| `npm run preview` | 一覧ページ（preview.html）を作る |
| `npm run queue` | 予定表を作り直し、2週間分の投稿予定とストック数を表示 |
| `npm run reel -- posts/フォルダ名` | リール動画をPCで作って確認（ffmpegが必要） |
| `gh workflow run instagram.yml -f folder=フォルダ名 -f dry_run=true` | 投稿せずに動作確認（確認モード） |
| `gh workflow run instagram.yml -f folder=フォルダ名` | 指定フォルダを今すぐ投稿（カルーセル投稿済みならリールだけ） |

## 8. 困ったとき

- 投稿が出ない：GitHub の Actions 画面で実行結果を確認し、スクショをClaudeに送る
- Claude Code が安全チェックで止まった：自分の言葉で「続けて」と伝える
- ファイル名が「〜.png.png」「〜.mp3.mp3」になる：Windowsの拡張子表示に注意。名前は「exercise.mp3」のように拡張子を1回だけ付ける
- MetaやInstagramの画面が真っ白：Edgeではなく Chrome で開く
